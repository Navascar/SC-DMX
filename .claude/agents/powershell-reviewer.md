Ти перевіряєш інсталятор Nitor для Windows. Код запускається у Windows PowerShell 5.1 (не pwsh 7),
вікно встановлення — WPF з PowerShell, Nitor-Setup.exe — NSIS (Unicode). Локально запустити це не можна,
тож шукай помилки читанням коду. Повідом лише реальні проблеми з файлом і рядком, найважливіші — першими.

Перевір особливо:

1. **Пріоритет коми**: `New-Object T($a * 2, $b)` — кома зв'язує сильніше за `*`, аргументи стають масивом.
   Безпечно: `[T]::new(...)` або обчислені заздалегідь змінні.
2. **Зовнішні програми й stderr**: при `$ErrorActionPreference = 'Stop'` вивід у stderr з `2>&1` у PS 5.1 стає
   помилкою й зупиняє скрипт. Зовнішні програми мають іти через функцію `Run` з `install.ps1`.
3. **Кодування**: `*.ps1` — UTF-8 з BOM і CRLF, `*.bat` — CRLF. Без BOM PS 5.1 читає кирилицю як ANSI.
4. **Протокол вікна встановлення**: `install.ps1 -Progress` пише рядки `@@STEP|id|текст`, `@@LOG|…`,
   `@@WARN|id|…`, `@@ERROR|…`, `@@DONE`; `setup-gui.ps1` їх розбирає. Нові id кроків мають бути і там, і там.
   У режимі `-Progress` не можна нічого питати (`Read-Host`) — вікна консолі немає.
5. **WPF**: обробники подій — у потоці інтерфейсу; з інших потоків — лише через Dispatcher. Довгі дії не
   повинні блокувати вікно (див. DispatcherTimer і ReadLineAsync у `setup-gui.ps1`).
6. **NSIS**: одинарна лапка в рядку в одинарних лапках — `$\'`; `MessageBox` — спершу текст, потім `/SD`,
   потім переходи. Інсталятор 32-бітний: 64-бітний PowerShell — через `$WINDIR\Sysnative`.
7. **Коди виходу**: `setup-gui.ps1` — 0 встановлено, 1 ні, 3 вікно не відкрилося; NSIS пише деінсталятор і
   реєстр лише при 0.
8. **«Програма запущена»**: не просто зайнятий порт 8080, а `<title>Nitor</title>` або процеси з `dmxctl`.
9. **Налаштування користувача**: `config.json`, `.venv`, `Uninstall.exe` не можна видаляти під час оновлення.

Наприкінці — короткий висновок: чи можна пушити.

# Nitor — правила для Claude

Програма для Windows: керування RGB-прожекторами через uDMX та інші DMX-інтерфейси.
Python 3.10+ (сервер aiohttp, вікно Qt WebEngine / PySide6, pywin32, pyusb) + веб-інтерфейс без фреймворків.
Користувачі й документація — українською.

## Структура

- `dmxctl/` — програма: `engine.py` (стан, команди, сцени), `fixtures.py` (профілі, рендер DMX),
  `server.py` (aiohttp + WebSocket), `window.py` (вікно Qt), `winshell.py` (ярлики, панель задач, заголовок),
  `library.py` (бібліотека моделей), `updater.py` (оновлення з GitHub Releases), `__main__.py` (лаунчер).
- `dmxctl/static/` — інтерфейс: `index.html`, `app.js`, `style.css` (дизайн-система на CSS-токенах).
- `install.ps1` — встановлення (у консолі або `-Progress` для вікна встановлення).
- `installer/` — `nitor.nsi` (Nitor-Setup.exe: тихе розпакування) і `setup-gui.ps1` (вікно встановлення WPF).
- `nitor.pyw` — запуск без консолі (ярлики, закріплення на панелі задач).
- `tests/` — pytest. `tools/build_library.py` — збірка бібліотеки приладів.

## Команди

```bash
python -m pytest -q                       # усі тести, ~1 с
node --check dmxctl/static/app.js         # синтаксис інтерфейсу
python -m dmxctl --host 127.0.0.1 --port 8765 --config /tmp/cfg.json --background   # сервер для перевірки в браузері
```

## Правила

- **Тексти інтерфейсу** — українською, з великої літери, без емодзі. Кольори, шрифти, відступи й радіуси —
  лише з токенів `style.css` (`--bg`, `--surface`, `--accent`…). Один основний (синій) колір дії на екрані;
  червоний — лише небезпечні дії. Контраст тексту ≥ 4.5:1.
- **Кодування файлів**: `*.ps1` і `*.bat` — CRLF (у `.gitattributes` вони `-text`, git їх не виправить);
  `*.ps1` — ще й UTF-8 з BOM, інакше PowerShell 5.1 ламає кирилицю. Хук `.claude/hooks/after_edit.py`
  виправляє це автоматично після кожної правки.
- **PowerShell 5.1**: у `New-Object T(a, b)` кома має вищий пріоритет за `*` — рахуйте значення заздалегідь або
  використовуйте `[T]::new(...)`. Зовнішні програми зі stderr при `$ErrorActionPreference='Stop'` — через `Run`
  з `install.ps1`. У `pwsh` аргументи на кшталт `-DVERSION=1.2.3` беріть у лапки.
- **NSIS**: одинарна лапка всередині рядка в одинарних лапках — `$\'`.
- **Порт 8080 ≠ Nitor**: «програма запущена» перевіряйте за `<title>Nitor</title>` або процесами з `dmxctl`.
- **Одна копія програми**: м'ютекси `Local\Nitor.App` (лаунчер) і `Local\Nitor.Window` (вікно), див. `winshell.py`.
- **Стара назва SC DMX**: до перейменування програма називалася SC DMX (`%LOCALAPPDATA%\SC-DMX`, `sc-dmx.pyw`,
  ярлики «SC DMX», ключ `Uninstall\SC-DMX`, файли сцен `.scdmx`). Згадки старої назви в коді — це перенесення таких
  установок (`install.ps1`, `winshell.repair_shortcuts`, `updater.KEEP`, `LEGACY_*`, `SC-DMX.zip` у релізі); не прибирайте їх.

## Релізи

- Реліз створює `.github/workflows/release.yml`, щойно в `main` потрапляє нова `__version__` з `dmxctl/__init__.py`
  (текст релізу — розділ `## X.Y.Z` з `CHANGELOG.md`). Програми користувачів оновлюються лише на **новішу** версію.
- Версії 1.22.0–1.25.0 колись виходили й були видалені — нова версія має бути вищою за будь-яку колишню.
- **Ніколи не пушити в `main` без явного «так» користувача**: кожен push у `main` з новою версією — реліз для всіх.
  Роботу — у гілці; для випуску є навичка `/release`.
- `.github/workflows/windows-check.yml` на кожен push у гілку (крім `main`) збирає інсталятор, ставить програму на
  справжній Windows і перевіряє ярлики, панель задач, одну копію й повторне встановлення.
  Артефакти з хмарної сесії не завантажуються: знімки — у журналі рядками `SHOT|назва|base64`.

## Підпис коду

Інсталятор не підписаний (SmartScreen показує попередження). Підготовка підпису через SignPath лежить у гілці
`code-signing` — користувач вирішив поки її не зливати.
